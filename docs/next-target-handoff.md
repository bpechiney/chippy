# Next-target handoff

Forward-looking brief for the next emulator in the chippy → Game Boy → NES → SNES trajectory (see ADR 0010). This file is **living** — bullets get added the moment a chippy lesson crystallizes, not deferred to retro time. At Game Boy kickoff, this is the literal first read; at NES and SNES kickoff, re-read to confirm bullets still apply and promote any rung-specific lessons captured in interim retros.

Each bullet should link back to the chippy retro that motivated it (e.g., "see `docs/retros/M3.md`").

## Do

- **Two-artifact split (core module + thin exe) from day one.** Pays off immediately: CI matrix never resolves a graphics dep, headless determinism is enforceable by construction, the next emulator's test ROMs run on the test runner. (See `docs/retros/M0.md`.)
- **Field-by-field `serialize`/`deserialize` from the first commit, never `std.mem.asBytes` on a struct.** Padding bytes inside structs are ABI- and compiler-version-dependent; raw struct serialization breaks save-state files when fields move. Same shape Game Boy will need across MBC variants and that NES/SNES will need across mapper and expansion-chip variants. (See `docs/retros/M0.md`, reviewer finding on PR #4.)
- **Brief out-of-line comments on "wraps quietly" semantics in core paths that handle ROM-derived addresses.** When chippy's `Bus.read16` masks at 12 bits, the wrap-around on the second byte fetch is non-obvious; Game Boy's 16-bit address space, NES's bank-switched space, and SNES's 24-bit space all have more legitimate boundary conditions, so the same documentation discipline matters more there. (See `docs/retros/M0.md`, reviewer finding on PR #4.)
- **Mechanical `/tdd` gate (ADR 0009) from day one.** A skipped `Skill` invocation on the first chippy M1 attempt cost an entire branch rollback — the agent followed red-green informally but bypassed the Planning phase and left no audit trail. The hook is ~30 lines of bash and zero ongoing cost; ship it before the first Game Boy sub-issue. If a future emulator restores `/feature-dev:feature-dev` per the existing reconsider note, generalize the gate into a configurable mandated-skill framework *before* that milestone starts, not during.
- **Persist the build-artifact cache (`.zig-cache/` or equivalent) between CI runs from the first runnable build.** `magic-nix-cache` preserves `/nix/store` but not the toolchain's own incremental-compile cache, so every PR rebuilds stdlib + dep portions cold. Chippy PR #22 measured a macOS Build step of 81s vs Ubuntu's 27s (3.0× ratio) and Build was the largest controllable line item on both runners. Pattern: `actions/cache@v4` step before Build, key = `${{ matrix.os }}` + hash(`build.zig` + `build.zig.zon` + `flake.lock`) + hash(`src/**/*.zig`), with restore-keys peeling back to OS+build-config, then OS-only, so partial hits still skip stdlib recompilation. Game Boy's surface is larger so the warm-cache savings will be larger too — ship this alongside the GB walking-skeleton CI, not as a follow-up. (See chippy issue #23.)
- **Gitignore Claude Code runtime artifacts (e.g. `.claude/scheduled_tasks.lock`) from the first commit.** The SessionStart cleanup hook (ADR 0011) skips merged-branch auto-cleanup whenever the working tree is dirty, and "dirty" includes untracked per-machine runtime locks written by Claude skills like `/schedule`. The hook logs "skipping" rather than failing, so the cleanup silently stops happening and merged branches accumulate locally. Audit which Claude skills write per-session/per-machine artifacts and ignore them alongside the existing `.claude/worktrees/` entry from the first commit. (See chippy issue #30.)
- **Decide where test fixtures (ROMs, golden snapshots) live BEFORE the first golden test, and pick the embed mechanism to match.** Zig restricts `@embedFile` to paths inside the module's *package directory* (the directory of the module's `root_source_file`). With `chippy_core` rooted at `src/core/root.zig`, the package directory is `src/core/`, so `@embedFile("../../tests/test_roms/...")` is rejected at compile time even though the path resolves. ADR 0004 specified `@embedFile` *and* a `tests/test_roms/` layout — incompatible without action. Three viable shapes: (a) put fixtures inside the module directory (`src/core/test_fixtures/`) and keep `@embedFile`; (b) lift the module's package root to the project root via a top-level wrapper Zig file and keep `@embedFile` with `tests/...` paths; (c) read fixtures at runtime via `std.Io.Dir.cwd()` and accept CWD-coupling + per-test allocation. Chippy chose (c) under time pressure. For Game Boy, pick (a) or (b) up front and write the ADR to match — runtime reads don't compose well as the fixture count grows (mooneye-test-suite etc. is hundreds of ROMs). (See chippy issue #12.)
- **Make the bus's underlying memory array private from the first commit; opcodes touch RAM only through bus methods.** Chippy M2.9 (PR #60) added three new opcodes (FX33/FX55/FX65) that indexed `self.bus.ram[self.cpu.i +% k]` directly. The arithmetic looks fine — `cpu.i` is `u16`, RAM is `[4096]u8` — until you notice `+%` wraps at 16 bits, not 12, so a high-`I` ROM walks past `ram[4095]` and panics the host (rule-12 violation). The neighboring DXYN already routed through `bus.read8` (which masks `& 0x0FFF`), but the pattern wasn't enforced; three independent reviewer agents caught the bug only because they happened to read `bus.zig` for prior art. On Game Boy the bus does *real* work — MBC bank selection, MMIO routing, OAM/VRAM access gating during PPU modes — so direct array indexing is structurally wrong, not just a rule-12 footgun. Either make the memory field unexported (`memory: [N]u8` with no `pub` accessors) so the type system enforces the invariant, or add a CI grep test that flags `bus.ram[` / equivalent outside the `Bus` module from the first commit. (See chippy PR #60, issue #61.)
- **CI: path-filtered with always-running gate from day one.** Heavy build/test should not run on docs-only / hooks-only / ADR-only diffs. Pattern: a `changes` job (native `git diff` against `pull_request.base.sha` / `push.before` + `grep -qvP` against a deny-list regex) sets `code=true` for any file outside docs/hooks; a matrix `test` job gates on `code=true`; a tiny always-running `required` job (`needs: [changes, test]`, `if: always()`) is the **sole** branch-protected check — passes vacuously when `test` was skipped, fails iff `changes` errored or `test` failed/cancelled. Deny-list (fail-open: forgetting an entry wastes runner time, allow-list would silently skip an untested merge). Single workflow (no two-file inverse-mirror drift). Native shell instead of `dorny/paths-filter` because the trigger surface is tiny (no force-push to a protected branch, no fork PRs, no schedule/workflow_dispatch); revisit only if multi-group filters appear. **Two-pass `.github/` split:** the deny-list excludes `^\.github/(?!workflows/)` (PCRE negative lookahead, requires `grep -P` → ubuntu-only `changes` job) so dependabot configs / issue templates / labelers skip heavy CI while workflow file changes still trigger the integration test against the real `nix develop -c zig build` invocation. The `^[^/]+\.md$` clause is anchored to single-segment paths so a hypothetical `src/INTERNALS.md` is not silently misclassified as docs. (See chippy issue #20.)

## Avoid

- **`cachix/install-nix-action` on macOS runners.** Pre-provisioned `_nixbld1` collides with `eDSRecordAlreadyExists`. Use `DeterminateSystems/nix-installer-action@v17` instead. **Don't pair it with `magic-nix-cache-action@v9`:** officially deprecated 2025-02-01, currently no-ops on save/restore (`Cache service responded with 400`), and added 9–13s of pure overhead per chippy job. For chippy-scale Nix closures (handful of stock nixpkgs + one pinned toolchain) `cache.nixos.org` covers cold runs adequately. Larger Nix closures may justify `DeterminateSystems/flakehub-cache-action@v9` — but that needs a `permissions:` block (`id-token: write`, `contents: read`) plus a FlakeHub.com signup, so weigh the auth-surface and signup cost against measured savings before adding it. (See `docs/retros/M0.md`, chippy issue #25.)
- **Cold-read reviewer agents without the linked issue body.** The `feature-dev:code-reviewer` agent run on PR #4 read `CLAUDE.md`, `CONTEXT.md`, the ADRs, and the diff — but did **not** fetch the GitHub issue listing the acceptance criteria, and so flagged in-spec methods (`runUntil`, `deinit`) for removal. **For the next emulator, every reviewer-agent prompt must include either the issue body inline or an explicit `gh issue view` instruction.** (See `docs/retros/M0.md`.)
- **GitHub task-list checkboxes with descriptive prefixes.** `- [ ] **M0 — ...** → #1` does not auto-tick when #1 closes; only the bare `- [ ] #1` form does. Future roadmaps should use the bare form, or accept manual ticks. (See `docs/retros/M0.md`.)

## Reconsider

- **Tier 2 CLI debug REPL was deferred to "on demand" for chippy.** Game Boy per-frame instruction count is roughly four orders of magnitude over chippy's (~70k cycles/frame at 4 MHz vs ~12 cycles/frame at 700 Hz), and full state no longer fits in a `std.debug.print`; revisit at Game Boy kickoff whether the REPL should land in the GB walking skeleton rather than waiting for a forcing function. NES and SNES amplify the same argument.
- **The `serialize` save-state format is currently field-by-field with no version header.** Fine for chippy (one schema version, lifetime measured in months). For Game Boy onward — multiple MBC variants, eventual save-state forwards-compat across the trajectory — add a 4-byte magic + 2-byte version at the front from the first GB commit.
- **CI runs `nix develop -c zig fmt --check`. The `fmt` step is currently after build and tests** — fast-failing is generally better. Reorder for the next emulator so a formatting violation is the first red.
- **Cross-model adversarial review (e.g., Codex reviewing Claude PRs).** Considered for chippy 2026-05-02 and deferred. The evidence base is thin — self-consistency, multi-agent-debate, and LLM-as-judge literature exists, but nothing rigorous specifically on cross-model adversarial code review reducing shipped bugs. For chippy the single Claude reviewer + CI matrix has been sufficient. For Game Boy and beyond the shared-blind-spot risk grows with codebase size, so revisit at Game Boy kickoff. **Hard enforcement is the bar** — if it can't ship as a CI job + branch-protection check (server-side, not Claude self-policing), skip it. If pursued: run as a non-blocking GitHub Actions job for ~10 PRs first, track findings vs false positives, flip to blocking only if Codex catches ≥1 real issue the Claude reviewer missed across that trial. Otherwise delete the workflow and record the negative result here.
- **`/feature-dev:feature-dev` was deprecated for chippy in favour of `/tdd` as the universal implementation method (ADR 0008).** It worked because PRD-first discipline (ADR 0007) settles shape before implementation, and chippy's surface is small enough that one architect's read of the PRD is enough. Game Boy has more legitimate shape ambiguity (MBC variants, sub-instruction M-cycle/T-cycle accuracy, GBC variant decision, save-state forwards-compat). Decide at Game Boy kickoff whether to keep `/tdd`-only or restore `/feature-dev:feature-dev` for genuinely ambiguous milestones — driven by whether the PRD process is producing settled-enough public surfaces, not by milestone size alone.
