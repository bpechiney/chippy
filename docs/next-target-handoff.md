# Next-target handoff

Forward-looking brief for the next emulator in the chippy → Game Boy → NES → SNES trajectory (see ADR 0010). This file is **living** — bullets get added the moment a chippy lesson crystallizes, not deferred to retro time. At Game Boy kickoff, this is the literal first read; at NES and SNES kickoff, re-read to confirm bullets still apply and promote any rung-specific lessons captured in interim retros.

Each bullet should link back to the chippy retro that motivated it (e.g., "see `docs/retros/M3.md`").

## Do

- **Two-artifact split (core module + thin exe) from day one.** Pays off immediately: CI matrix never resolves a graphics dep, headless determinism is enforceable by construction, the next emulator's test ROMs run on the test runner. (See `docs/retros/M0.md`.)
- **Field-by-field `serialize`/`deserialize` from the first commit, never `std.mem.asBytes` on a struct.** Padding bytes inside structs are ABI- and compiler-version-dependent; raw struct serialization breaks save-state files when fields move. Same shape Game Boy will need across MBC variants and that NES/SNES will need across mapper and expansion-chip variants. (See `docs/retros/M0.md`, reviewer finding on PR #4.)
- **Brief out-of-line comments on "wraps quietly" semantics in core paths that handle ROM-derived addresses.** When chippy's `Bus.read16` masks at 12 bits, the wrap-around on the second byte fetch is non-obvious; Game Boy's 16-bit address space, NES's bank-switched space, and SNES's 24-bit space all have more legitimate boundary conditions, so the same documentation discipline matters more there. (See `docs/retros/M0.md`, reviewer finding on PR #4.)
- **Mechanical `/tdd` gate (ADR 0009) from day one.** A skipped `Skill` invocation on the first chippy M1 attempt cost an entire branch rollback — the agent followed red-green informally but bypassed the Planning phase and left no audit trail. The hook is ~30 lines of bash and zero ongoing cost; ship it before the first Game Boy sub-issue. If a future emulator restores `/feature-dev:feature-dev` per the existing reconsider note, generalize the gate into a configurable mandated-skill framework *before* that milestone starts, not during.

## Avoid

- **`cachix/install-nix-action` on macOS runners.** Pre-provisioned `_nixbld1` collides with `eDSRecordAlreadyExists`. Use `DeterminateSystems/nix-installer-action@v17` + `magic-nix-cache-action@v9` instead. (See `docs/retros/M0.md`.)
- **Cold-read reviewer agents without the linked issue body.** The `feature-dev:code-reviewer` agent run on PR #4 read `CLAUDE.md`, `CONTEXT.md`, the ADRs, and the diff — but did **not** fetch the GitHub issue listing the acceptance criteria, and so flagged in-spec methods (`runUntil`, `deinit`) for removal. **For the next emulator, every reviewer-agent prompt must include either the issue body inline or an explicit `gh issue view` instruction.** (See `docs/retros/M0.md`.)
- **GitHub task-list checkboxes with descriptive prefixes.** `- [ ] **M0 — ...** → #1` does not auto-tick when #1 closes; only the bare `- [ ] #1` form does. Future roadmaps should use the bare form, or accept manual ticks. (See `docs/retros/M0.md`.)

## Reconsider

- **Tier 2 CLI debug REPL was deferred to "on demand" for chippy.** Game Boy per-frame instruction count is roughly four orders of magnitude over chippy's (~70k cycles/frame at 4 MHz vs ~12 cycles/frame at 700 Hz), and full state no longer fits in a `std.debug.print`; revisit at Game Boy kickoff whether the REPL should land in the GB walking skeleton rather than waiting for a forcing function. NES and SNES amplify the same argument.
- **The `serialize` save-state format is currently field-by-field with no version header.** Fine for chippy (one schema version, lifetime measured in months). For Game Boy onward — multiple MBC variants, eventual save-state forwards-compat across the trajectory — add a 4-byte magic + 2-byte version at the front from the first GB commit.
- **CI runs `nix develop -c zig fmt --check`. The `fmt` step is currently after build and tests** — fast-failing is generally better. Reorder for the next emulator so a formatting violation is the first red.
- **Cross-model adversarial review (e.g., Codex reviewing Claude PRs).** Considered for chippy 2026-05-02 and deferred. The evidence base is thin — self-consistency, multi-agent-debate, and LLM-as-judge literature exists, but nothing rigorous specifically on cross-model adversarial code review reducing shipped bugs. For chippy the single Claude reviewer + CI matrix has been sufficient. For Game Boy and beyond the shared-blind-spot risk grows with codebase size, so revisit at Game Boy kickoff. **Hard enforcement is the bar** — if it can't ship as a CI job + branch-protection check (server-side, not Claude self-policing), skip it. If pursued: run as a non-blocking GitHub Actions job for ~10 PRs first, track findings vs false positives, flip to blocking only if Codex catches ≥1 real issue the Claude reviewer missed across that trial. Otherwise delete the workflow and record the negative result here.
- **`/feature-dev:feature-dev` was deprecated for chippy in favour of `/tdd` as the universal implementation method (ADR 0008).** It worked because PRD-first discipline (ADR 0007) settles shape before implementation, and chippy's surface is small enough that one architect's read of the PRD is enough. Game Boy has more legitimate shape ambiguity (MBC variants, sub-instruction M-cycle/T-cycle accuracy, GBC variant decision, save-state forwards-compat). Decide at Game Boy kickoff whether to keep `/tdd`-only or restore `/feature-dev:feature-dev` for genuinely ambiguous milestones — driven by whether the PRD process is producing settled-enough public surfaces, not by milestone size alone.
