# Per-milestone PRD via `/to-prd`, before issue slicing

Each milestone from M1 onward starts with a Product Requirements Document published as a `prd`-labeled GitHub issue, generated via `/to-prd` from the prior context (post-retro discussion, prior-milestone outcomes, design conversations) and following the skill's template (Problem / Solution / User Stories / Implementation Decisions / Testing Decisions / Out of Scope). After triage, the PRD is sliced into implementation sub-issues with their own acceptance criteria; the PRD remains as the durable parent that sub-issues link back to. M0 is treated as a degenerate case — its PRD is the project plan plus the M0 implementation issue, since the milestone is a single foundational PR. Trade-off: an extra ceremony step per milestone in exchange for a structured handoff between design and implementation, an audit trail of SNES-relevant requirements as they emerge, and clean separation between "what we're building" (PRD) and "how we slice it" (sub-issues).
