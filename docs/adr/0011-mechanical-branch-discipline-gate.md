# Mechanical branch-discipline gate

A trio of project-level hooks (`.claude/hooks/check-branch-discipline.sh`, `post-merge-cleanup.sh`, `session-start-sync.sh`) enforces the per-PR loop's branch hygiene without any agent prompting. The PreToolUse hook blocks `Edit`/`Write`/`MultiEdit` on any in-repo path while the current branch is `master` or while the current branch's upstream tracking shows `[gone]`; the PostToolUse hook fires after any Bash command containing `gh pr merge`, verifies via `gh pr view --json state` that the PR for the current branch is `MERGED`, and then runs `git checkout master && git fetch origin --prune && git pull --rebase origin master && git branch -D <merged-branch>`; the SessionStart hook (matchers `startup`, `resume`, `clear` — `compact` is intentionally omitted because compaction does not change branch state) does a `git fetch --prune origin` and runs the same cleanup if the current branch is merged. ADR 0009 closed the "did the agent invoke `/tdd`?" gap; this ADR closes two parallel gaps that surfaced after it: the `/grill-with-docs` invocation that introduced ADR 0010 (#17) edited `CONTEXT.md` and ADRs on master before branching, forcing a full reconstruction onto a fresh branch, and every merge to date has required manual user prompting to checkout master, pull --rebase, and delete the merged local branch — which agents reliably skip without enforcement, leaving the next sub-issue's work to begin on stale state. Soft alternatives — warning-only nudges, a Stop-hook audit pass, requiring a `^[0-9]+-` issue-branch pattern that would conflict with ADR 0009's deliberate exception for harness branches — were rejected because the cost of a rollback dwarfs the cost of a hard block (per ADR 0009's lesson) and because the per-PR loop's "branch off latest origin/master" step is non-negotiable but un-enforced by anything else. A full per-edit `git fetch` was rejected as too slow; instead, freshness is enforced socially via the on-master block message (which prescribes `git fetch origin && git checkout -b <N>-<slug> origin/master` literally) and mechanically by the SessionStart fetch+cleanup catching every `/clear` and resume. The block message follows a two-path structure naming the organic-discovery case explicitly: file an issue first via `gh issue create`, then branch as `N-slug` — keeping policy adherence in the agent's face on every blocked edit without forcing a `^[0-9]+-` regex check that would also block legitimate harness work. All three hooks fail open whenever they cannot do their job (missing `jq` or `gh`, outside the repo, `git rev-parse` failure, dirty working tree, rebase conflict on master) so a harness bug never silently masquerades as a discipline violation; the rebase-conflict path explicitly aborts the rebase and refuses to delete the merged branch so the user can resolve manually. `flake.nix` adds `pkgs.jq` and `pkgs.gh` to document the hook dependency, though hooks resolve them from the parent shell's `PATH` at runtime since Claude Code typically launches outside `nix develop`. Bash-based file mutations (`echo > file`, `sed -i`) bypass the PreToolUse hook — same gap as ADR 0009; per CLAUDE.md rule 9, generalize when a second skipped-hook failure justifies the framework, not before. The trade-off is one extra ceremonial branch-creation step on master (already required by the per-PR loop) and a roughly one-second `git fetch` on every fresh-context boundary, in exchange for structurally-impossible-to-skip branch discipline and post-merge cleanup. One-time bootstrap caveat: the PR introducing this ADR will not itself be auto-cleaned because the new `settings.json` is not loaded into the running session's hook cache until a fresh session reads it — manual cleanup of branch `18-mechanical-branch-discipline` after merge, then the gate becomes self-sustaining.
