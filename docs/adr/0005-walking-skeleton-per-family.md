# Walking-skeleton + per-family opcode granularity; pinned meta-issue as roadmap

Work is sliced as a walking skeleton (M0 — end-to-end stub that loads a ROM, fetches an opcode, returns) followed by per-family opcode milestones (display+system, constants/assignment, ALU, conditionals, jumps/calls, random+draw, input, timers/I-ops/BCD/memory) and supporting milestones (M3 quirks, M4 input, M5 audio, M6 raylib frontend, M7 Tier 1 polish). Roadmap state lives in a pinned GitHub meta-issue (`bpechiney/chippy#2`) with a checklist linking sub-issues — *not* in `CONTEXT.md`, which is reserved for stable domain language; closing a sub-issue auto-checks its meta-issue box. The trade-off is more issue-management ceremony than a flat TODO file would need, in exchange for always-working state after every merge, the earliest possible visual proof of life (Timendus IBM logo at M1), and a harness exercise on tractable units that future agents can pick up via `gh issue list --label ready-for-agent`.
