# Audio as `isBeeping` predicate plus opt-in `AudioSink` recording seam, frame-aligned post-tick cadence

`Machine.isBeeping(): bool` (returning `audio.isBeeping(self.timing.sound_timer)` from the M0-shipped predicate in `audio.zig`) is the runtime API; ROMs and frontends observe the audible-or-not state through that single bit. Alongside it, `audio.zig` grows an opt-in `AudioSink` test-time recording seam — a bare struct with `ctx: *anyopaque` and `write: *const fn (ctx: *anyopaque, beeping: bool) anyerror!void`, structurally identical to `TraceSink` modulo the payload type and the `anyerror!void` return (callers swallow errors at the dispatch site since audio is non-essential to ROM correctness) — wired into `Options.audio_sink: ?AudioSink = null` and dispatched once per `runFrame` *after* the existing `tickTimers()` call. The post-tick cadence means the sink reads `sound_timer` after the 60 Hz decrement, so a sub-frame transient (FX18 set + cleared inside the same N cycles before any tick) is inaudible by VIP semantics and intentionally invisible to the sink — the test contract for ST=1 set in frame 1 is a single-frame `[false]` record because the timer ticked from 1 to 0 before the sink fired. The sink fires *only* from `runFrame`, never from `step` or `runCycles` — by construction, because `runCycles` does not call `tickTimers`. Four alternatives were rejected with concrete failure cases. Option (a), **sample emission inside core** (audio.zig synthesizes square-wave samples at a chosen sample rate and the sink receives byte-typed audio), forces an arbitrary sample-rate decision with no chippy correctness consequence (vanilla CHIP-8 has no pitch, waveform, or volume), commits `Audio` to phase state inside `Machine.serialize` (rule 10 friction with greenfield save-state shape), and turns cross-runner equality into "samples must hash equal" — far more brittle than 60-byte bool-stream byte-equality at one second of recording. Option (b), **mid-frame / per-FX18 cadence** (sink fires on every `sound_timer` write or on every cycle), captures inaudible transients (FX18-set-then-clear inside a single 11-cycle frame would emit two write events for a state never audible to a real VIP), decouples from the 60 Hz tick contract that gates audibility, and breaks the bool-stream-byte-N = frame-N alignment that future goldens rely on for `o(1)` regression diff localization. Option (c), **bare predicate, no sink** (`golden_harness` polls `isBeeping()` per-frame manually from the test loop), works for chippy's 60-byte/sec bool stream but punts the GB rehearsal seam — Game Boy's APU sink (per-cycle, per-channel, sample mixing) cannot be retrofitted at GB kickoff under deadline pressure if the chippy seam shape was never landed; the M5 milestone's secondary purpose per ADR 0010 is exactly to land seams the next emulator inherits. Option (d), **frontend-wired runtime sink** (sink is a runtime audio output path that raylib hooks at M6), adds fn-pointer call overhead to the audible path with no audible payoff (raylib will use `isBeeping()` to gate a square-wave generator in the frontend, not consume per-frame events from core), conflates a test-time recording surface with a runtime IO surface, and tempts a future frontend-side bug to push state into core. The bundling of cadence + payload + contract-shape into one ADR follows ADR 0013's precedent: the rejected alternatives interact (e.g. option (a)'s sample-rate decision is incoherent without committing to option (b)'s mid-frame cadence; option (d)'s runtime path is incoherent without option (a)'s sample emission), so splitting them into per-decision ADRs would obscure the structural reasoning. **Promote at M5 close:** the structural pattern (opaque ctx + fn pointer + opt-in via `Options` + null fast path + same dispatch convention as `TraceSink` + frontend never wires it) carries forward to GB's APU sink one-to-one, but the bool-per-frame format does not — GB needs per-cycle, per-channel, sample-mixing payloads. The cross-reference is lifted into `docs/next-target-handoff.md` alongside the existing M2.10 `TraceSink`-line-format-doesn't-carry bullet so the Game Boy emulator inherits both halves of "the seam carries forward; the format does not."
