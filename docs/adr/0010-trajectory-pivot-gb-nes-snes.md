# Project trajectory pivot: chippy → Game Boy → NES → SNES

The original project trajectory (chippy → SNES, recorded in `~/.claude/plans/we-need-to-nail-smooth-bird.md` and threaded through ADRs 0001, 0002, 0006, 0007, 0009 and `docs/snes-handoff.md`) is replaced by a four-stage ladder: chippy → Game Boy → NES → SNES. Each rung is a tractable complexity step over the previous one (CHIP-8 → GB adds bank-switching mappers, sub-instruction cycle counting via M-cycles/T-cycles, and a real APU; GB → NES adds 6502 + cycle-accurate PPU dot timing + mapper variety; NES → SNES extends 6502 to 65816 and PPU dot timing to Mode 7). The skip-NES alternative (GB → SNES directly) was rejected because GB's LR35902 is a Z80 derivative and doesn't rehearse the 6502 → 65816 CPU lineage that SNES demands. Each rung also commits to the same AI-harness discipline as chippy — TDD, PRD-first, evidence-grounded merges — so the harness gets three more learning loops before SNES, which was the original "too big a leap" problem.

The architectural reasoning in ADRs 0001 (two-artifact split), 0002 (vanilla-only quirks struct), 0006 (Tier 1 debug affordances), 0007 (per-milestone PRD), and 0009 (mechanical `/tdd` gate) stands without supersede — those decisions still carry forward, only the name of the next system changes. References to "SNES" in those ADRs should be read as "the next emulator, with Game Boy the immediate target." Triggers anchored to "next-emulator kickoff" semantics — the `/improve-codebase-architecture` sweep mandated by `CLAUDE.md`, the Reconsider items in `docs/next-target-handoff.md` (Tier 2 CLI REPL forcing function, save-state magic+version header, CI fmt step ordering, cross-model adversarial review, `/feature-dev:feature-dev` reconsideration) — fire at Game Boy kickoff, not SNES kickoff. Deferrals anchored to specific SNES-tier complexity remain anchored there: Tier 3 graphical debugger per ADR 0006 (address-space size and per-frame instruction count) and Windows host support stay deferred to SNES, with a re-evaluation at Game Boy kickoff but no pre-commit. `docs/snes-handoff.md` is renamed `docs/next-target-handoff.md` and reframed for the new trajectory; `~/.claude/plans/we-need-to-nail-smooth-bird.md` is preserved as a frozen historical artifact with a SUPERSEDED banner pointing to this ADR. The trade-off is one extra ADR plus mechanical doc edits in exchange for a project trajectory that doesn't ask the AI harness to debut on a system three complexity steps removed from the one it was rehearsed on.
