## What worked

- **Per-PR loop scaled to 11 sub-issues in one day with no rollbacks.** PRD-first → per-sub-issue branch → `/tdd` → `/simplify` → `/commit-push-pr` → `/review` → CI matrix → merge, repeated 11 times. Cold-read review caught the M2.9 bus-array-indexing rule-12 footgun in flight (three independent reviewer agents flagged it before merge); the lesson got promoted to handoff via #61/#62 mid-milestone rather than waiting for retro time, exactly as the lessons-capture rule prescribes.
- **The nibble-helper refactor landed when the M1 retro said it should — not before.** M2.4 (PR #54) extracted `opX/opY/opN/opNN/opNNN` into `src/core/decode.zig` *after* M2.3 shipped the first 8XYN family and the duplication crossed the ~10-call-site threshold. Mechanical find-and-replace, scoped via `/request-refactor-plan` (issue #53), shipped as its own PR per CLAUDE.md's no-refactors-mixed-with-features convention. Rule 9 in action.
- **Cross-runner determinism gate held on the keystone test's first push.** corax+'s 256-byte packed framebuffer was byte-identical on `ubuntu-latest` and `macos-latest` on the first CI run for PR #64. The Timendus reference PNG check (sample each cell, compare against the packed bytes) was added pre-commit and confirmed pixel-exact match against the canonical "all OK" screen — a stronger gate than the issue required, achievable only because chippy_core stays free of wall-clock and OS randomness.
- **PRD-up-front decisions held under contact.** The PRD's "write VX before VF" rule (8XY4/5/7), the "shift VY into VX" vanilla semantics for 8XY6/8XYE, the `// M3: gate on Quirks.X` placeholder convention, the 4-bit-mask wrap on stack `sp`, and the `Machine.prng`-from-`Options.rng_seed` random source all shipped as specified. Zero ADR-grade decisions deferred mid-milestone.

## What didn't

- **The corax+ cycle-count estimate was off by ~30×.** M2.11's PRD said "estimate 10k–50k cycles; pick to nearest 1000 for legibility." Empirically, the framebuffer stabilizes by cycle ~350 — the ROM's 22 opcode self-tests finish much faster than the PRD anticipated. Settled on N=1000 (still rounded to nearest 1000, ~3× safety margin, sub-millisecond). The PRD estimate didn't cause a problem because the empirical pick rule was explicit, but anchoring estimates that high added ~5 min of "is something wrong?" verification when every cycle count from 500–50k produced the same bytes.
- **M2.9's bus-array-indexing footgun nearly merged.** FX33/FX55/FX65 were the first opcodes to index `self.bus.ram[self.cpu.i +% k]` directly — `cpu.i` is `u16`, RAM is `[4096]u8`, and `+%` wraps at 16 bits not 12, so a high-`I` ROM walks past `ram[4095]` and panics the host (rule-12 violation). Caught only because three independent reviewer agents happened to read `bus.zig` for prior art and noticed the neighboring DXYN routes through `bus.read8` (which masks `& 0x0FFF`) while the new opcodes didn't. Fixed in-flight; lesson promoted to handoff (#61/#62) the same day. The structural fix — make `Bus.ram` private or grep-test for direct access — is a Game Boy-bound ADR, not a chippy patch (only 3 sites today).
- **`std.testing.environ.getPosix` is still the only way to read env vars from tests.** No drift since M1.5 here, but the API is non-obvious enough that I had to re-grep on M2.11. Captured in M1's retro already; no new lesson.

## Surprises

- **The trace writer + sprite-draw log lined up with no further design churn.** ADR 0006 specified the `TraceSink`-shaped seam in M0; the M0 + M1 disasm cases produced the mnemonics; M2.10 (PR #63) just wired the emit point. Total diff was small (~150 lines) because every shape decision had been settled upstream. The Tier 1 affordances really did "earn their keep" on the schedule M0/M1 had budgeted.
- **No `/diagnose` invocations across the whole milestone.** Every red test was a localized opcode bug surfaced by the per-opcode test in the same commit. The TDD discipline kept the search radius small enough that root-cause was usually the most-recently-edited line. M0's debugging loops are gone — projected forward, this is what "tests as flashlight" looks like with a settled per-PR loop.
- **All 11 PRs landed on the first CI push.** Same observation as M1's "all 7 PRs landed on first push" — the per-PR loop continues to produce green-on-first-push as the default. The cost-per-PR has stayed flat as the codebase grew ~3×.

## Carry forward to M3

- **`Quirks` reads exist at every gated site with `// M3: gate on Quirks.X` comments — link the M3 PRD's quirks-test sub-issues to those exact sites.** The vanilla branch is the only one running today; M3's job is to add the alternate branch behind the flag, not to discover where the gates go. Sites: `8XY1/2/3` VF-reset (`vf_reset_on_logical`), `8XY6/8XYE` shift source (`shift_in_place`), `BNNN` index register (`jump_uses_vx`), `FX55/FX65` I-increment (`no_index_increment`).
- **The `assemble(.{...})` + `disasm` per-opcode rhythm extends to M3 quirks ROMs.** Same template; new ROMs likely vendor more Timendus suite entries (`4-flags.ch8`, `5-quirks.ch8`).
- **`/grill-with-docs` precedes `/to-prd` for M3 per CLAUDE.md.** Heavyweight prep is the spec; quirks have enough ambiguity (which suite, which defaults, which gates) to warrant the grilling pass.

## Carry forward to next emulator (Game Boy)

- **Bus-array-indexing footgun → bus-private structural fix from day one** (already promoted via #61/#62). Either make the bus's memory field unexported or add a CI grep test for direct array access. Game Boy's bus does *real* work (MBC bank selection, MMIO routing, PPU-mode-gated VRAM/OAM access), so direct indexing is structurally wrong, not just a rule-12 footgun.
- **Verify against published reference screenshots when an emulator's test ROM has one.** corax+'s pixel-exact match against `Timendus/chip8-test-suite/pictures/corax+.png` (sample each cell, compare against the packed framebuffer) was a stronger gate than per-pixel byte-equality alone — it confirms not just determinism but *correctness against an external authority*. Mooneye, blargg, and dmg-acid2 all ship reference outputs; bake the comparison into the golden test from day one rather than only asserting against the locally-captured snapshot. Same code shape works (PNG → packed bits → `expectEqualSlices`).
- **Pick test-ROM cycle counts from empirical measurement, not PRD estimates.** chippy's PRD estimated corax+ stabilizes at 10k–50k cycles; reality was ~350. Game Boy's frame counts are roughly four orders of magnitude larger so the temptation to anchor on a "round number" estimate will be stronger; resist it. Run the ROM, hash the framebuffer at increasing cycle counts, take the smallest N where the hash stabilizes, then add a generous safety margin.
- **Tier 1 trace writer's line format `XXXX:OOOO MNEMONIC <state-delta>` is frozen for chippy** (per M2.10 design decision). Game Boy's per-cycle state is much richer (16-bit registers, 8-bit MBC bank, PPU mode, IF/IE flags); decide GB's trace format up front and resist trying to share chippy's exact bytes — different emulators have different state shapes and a forced-shared format would be a leaky abstraction at the trace boundary, not a clean reuse.
