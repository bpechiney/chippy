End state: all three keypad opcodes (EX9E, EXA1, FX0A) wired into `Machine.step`. Both Timendus keystone ROMs land as cross-runner-deterministic `.bin` goldens against four scripted-input checkpoints (`6-keypad.ch8`) and one menu-bypassed checkpoint (`5-quirks.ch8`). `StepResult.waiting_for_key` joins `.waiting_for_vblank` as a second blocking-opcode stall arm — exactly symmetric in shape per ADR 0013. `Keypad.last_released: ?u4` rename → `Keypad.awaiting_release: ?u4` with shifted semantics (claim slot owned by the active FX0A, null otherwise). `src/core/golden_harness.zig` extracted between M4.2 and M4.3 once the rule-of-three triggered; `src/core/scripted_input.zig` lands at its first real caller in M4.4 (rule 9). `runUntil` learns to break on `.waiting_for_key` and propagate the variant. Rule 13 (no deferring review-flagged gaps on speculation) and the per-PR loop's step 6 (lessons gate) both codified in CLAUDE.md mid-milestone.

## What worked

- **`/grill-with-docs` settled the FX0A two-phase shape ahead of M4.3.** Two alternatives explicitly rejected with reasons (consume `last_released` directly → fails on pre-FX0A noise; busy-wait inside `step` → violates O(1) `step` contract). ADR 0013 landed in the same commit as the contract change, so the rejected alternatives are recorded against `git blame`.
- **Per-PR loop scaled to 4 sub-issues + 4 tooling/docs PRs without losing cadence.** Implementation sub-issues all green-on-first-CI; the two interleaved structural PRs (#86 golden_harness, #90 lessons-gate) landed cleanly between sub-issues without disrupting the dependency graph.
- **The pre-flight-trace methodology caught two reachability surprises before they hit CI.** M4.2's empirical sweep across multiple cycle windows revealed FX0A reachability in 5-quirks's post-test reset loop (PRD said "FX0A out of scope"); M4.4's per-checkpoint hash-stability sweep at 50-cycle resolution found the cursor-blink plateau (`keypad-menu.png` reference). Both refined existing handoff bullets rather than landing as new traps.
- **Mid-milestone golden_harness extraction (rule of three) absorbed cycles-vs-frames + per-ROM-setup cleanly.** `runAndCompare(opts: RunOptions)` with `RunMode = union { cycles, frames }` and an optional `pre_run` hook lets 5-quirks's `pokeRam(0x1FF, 1)` and 6-keypad's scripted-input timeline coexist behind one signature. M5 / Game Boy inherit the deep-module shape, not a triplicated copy.
- **Cold-read review caught the `Machine.runCycles(1)` routing leak in `scripted_input.zig`.** The helper initially mutated `m.timing.cycles += 1` directly, paralleling `runCycles`. Review flagged the contract leak; fix routed every per-cycle step through `Machine.runCycles(1)`. Same review surfaced the FX0A trace count anomaly that anchored the M4.4 PRD pre-flight table.

## What didn't

- **The M4.2 PRD anchored on a too-narrow pre-flight trace window.** The trace at cycle 50 000 (still in the splash phase) concluded "FX0A is not exercised post-patch." Reality: FX0A fires 2 874 times across 9.8M cycles in the post-test reset-on-key-press loop. The mid-PR pivot landed a minimal FX0A stall (`.waiting_for_key` return, no consume) inside M4.2 — even though FX0A was supposed to be M4.3 territory. Recovered cleanly because the minimal shape was sufficient (the ROM never reaches consume-and-restart within N=15000), but cost ~one half-day of mid-PR re-shape. Refined the existing `pre-flight-trace` handoff bullet to require sampling boot / mid-test / post-test / idle windows, not just boot.
- **The `Cosmac-VIP-quirks.png` reference vendored on the M4-prep branch was a marketing screenshot, not a raw raster.** 848 × 661 (non-integer multiple of 64 × 32 — `848 / 64 = 13.25`); on inspection it's an Emma 02 emulator window inside macOS desktop, with multiple visible windows and OS chrome. The neighbouring `pictures/quirks.png` (768 × 384, clean 12× upscale, no chrome) is the actual reference. The vendoring step on the prep branch didn't open the file. Cost: mid-PR re-vendor; new handoff bullet.
- **M4.1 PR #81 deferred two reviewer-flagged gaps as "non-blocking follow-up" with prose-only justifications** — `V[X] & 0xF` mask-edge tests + the convention that every shipped opcode has a `disasm` entry. Both deferrals were rationalized by speculation about future coverage, not evidence. The deferrals were rejected, both gaps filled in the same PR, and rule 13 codified into CLAUDE.md alongside the work — encoding the M3.4 anti-pattern at a different scale.
- **Three docs-only follow-up PRs (#85, #88) plus a stray inline commit (90c2a26 / 55f1a58 for M4.2) made it clear the prose-only "lessons land now" rule was decaying into "lessons trickle in afterward."** Codified as per-PR-loop step 6 (the lessons gate) in CLAUDE.md via PR #90. Workflow violation now explicit and reviewer-checkable rather than a soft norm.

## Surprises

- **Both keystone goldens dropped runtime PNG-equality in flight.** A runtime PNG decoder for chippy was scoped at ~300 LOC of test-only, non-carry-forward code; cross-runner-deterministic `.bin` byte-equality + the eyeball-gate at PR review carries the same correctness load. Same scope reduction landed in M4.2 *and* M4.4 — the eyeball-gate path is now the load-bearing correctness anchor, with `.bin` regression byte-equality on the CI matrix.
- **`runFrame` vs `runCycles` was load-bearing for 5-quirks.** The first attempt at `runCycles(15000)` captured the splash screen indefinitely — `runCycles` advances the CPU but doesn't call `timing.tick()`, and 5-quirks pages between display states via the delay timer. Switched to `runFrame(120)`. Same trap caught at the cycles-vs-frames bullet promoted to handoff.
- **The `golden_harness` extraction at PR #86 absorbed three mostly-identical golden runners into one deep module without per-test-call-site churn.** Each call-site is now ~5 lines; the next golden lands as a one-line `runAndCompare` invocation. Promoted as the "pre-extract on the second test" bullet ahead of Game Boy's mooneye-test-suite scale.
- **No `/diagnose` invocations across the milestone.** Same observation as M2 and M3 — every "test went red" moment was either an expected red in the tracer-bullet cycle or a design-time empirical surprise the pre-flight-trace + cycle-stability-sweep methodology surfaced before CI. `/diagnose` may not be the right tool for chippy-shaped failures; remains in the kit for genuine cross-module mysteries.

## Carry forward to M5

- **Audio wires into the existing `timing.tick()` path; reuse the M3 vBlank infrastructure and ADR 0012's `cycles ≠ instructions` framing.** No new opcodes — sound-timer is already gated through the timer family that M2.8 wired.
- **M5 is heavyweight per CLAUDE.md per-milestone loop.** Precede `/to-prd` with `/grill-with-docs` to settle the sample-stream contract (does the core emit raw samples, square-wave on/off, or `isBeeping(): bool`?) and any cross-runner-determinism implications of audio.
- **The Timendus beep-test ROM is M5's keystone external check.** Apply the multi-window pre-flight trace methodology from the refined handoff bullet — sample boot / mid-test / post-test / idle for blocking-opcode reachability and any timer-driven gating.
- **The `golden_harness` is ready to host an audio-trace assertion path.** Plan `RunOptions` to grow an optional `audio_sink: ?*AudioSink` field rather than triplicating per-call-site setup.

## Carry forward to next emulator (Game Boy)

- **FX0A's two-phase blocking-opcode pattern → Game Boy JOYP / IRQ-blocking shape** — the new handoff bullet promoted from ADR 0013. chippy now has two living examples of "blocking opcode = real `step` stall, not cycle absorption" (DXYN's vBlank-wait, FX0A's GETKEY); both ship with cross-runner-deterministic byte-identical semantics. Game Boy's JOYP-poll-into-blocking-IRQ and Mooneye's wait-for-IRQ test sequences map directly onto the same shape.
- **All four M4.2-derived lessons already in handoff via PR #85** — cycles-vs-frames runner choice, raw-raster reference dimensions, multi-window pre-flight traces, standalone `.bin`-render eyeball-gate utility.
- **The golden_harness "pre-extract on the second test" lesson already in handoff via PR #88.** Game Boy's mooneye-test-suite ROM count makes pre-extraction non-optional from day one.
- **M4.4's oscillating-framebuffer + `runCycles(1)` routing lessons already promoted in PR #92.** Pin checkpoints to plateau centres; route test-only per-cycle drivers through `Machine.runCycles(1)` to inherit the cycle/halt contract.
- **Rule 13 (no deferring review-flagged gaps on speculation) already in handoff via line 23.** Ship from day one on Game Boy. If a *second* deferral-mode failure occurs, build a chippy-local `/review-strict` wrapper before the next milestone — phrase-blacklist hooks were considered and rejected as too brittle (false-positive cost erodes trust per ADR 0011's flake-tolerance budget).
